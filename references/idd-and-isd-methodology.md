## 1. What is an Instructional Design Document (IDD)?

An **Instructional Design Document (IDD)** is the macro-architectural contract and high-level blueprint for a learning project. It is authored during the **Design phase of ADDIE** (after Analysis is complete, but before detailed Storyboarding or tool development begins).

### The L&D Documentation Hierarchy:
```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        HIERARKI DOKUMENTASI INSTRUCTIONAL DESIGN                       │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 1. Needs Analysis Report   ➔ Diagnosis: kesenjangan performa, akar masalah, audiens   │
│ 2. INSTRUCTIONAL DESIGN    ➔ ARSITEKTUR MAKRO: Kontrak strategi, modul, asesmen,     │
│    DOCUMENT (IDD)             LMS, WCAG, kriteria evaluasi, dan RACI sign-off          │
│ 3. ISD Project Plan (WBS)  ➔ MANAJEMEN PROYEK: Timeline 16-minggu, jadwal review SME  │
│ 4. Course Blueprint        ➔ MATRIKS KURIKULUM: Modul, objektif, aktivitas, asesmen   │
│ 5. Storyboard / Script     ➔ DETAIL MIKRO: Teks per layar, instruksi visual, tombol   │
│ 6. Facilitator/Learner Doc ➔ MATERI DELIVERABLE: Panduan fasilitator, buku peserta     │
│ 7. Evaluation Report       ➔ EVALUASI DAMPAK: Analisis data Kirkpatrick L1 - L4       │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. Framework-Adaptive IDD Selection Matrix

A world-class Instructional Designer adapts the structure of the IDD to the specific pedagogical model that best serves the learning problem:

### 1. ADDIE Classic (Standard Corporate / Institutional Programs)
* **Best For**: End-to-end curriculum initiatives, enterprise-wide rollouts, long-term training programs.
* **IDD Specialization**: Strict 5-phase alignment, comprehensive needs analysis summary, multi-module matrix, Kirkpatrick Level 1–4 evaluation architecture.

### 2. SAM — Successive Approximation Model (Rapid / Agile / E-Learning)
* **Best For**: Rapid e-learning development, software training, fast-changing business environments.
* **IDD Specialization**: Replaces linear development with **Savvy Start**, Iterative Prototyping Loops (Alpha, Beta, Gold releases), rapid stakeholder review gates.

### 3. Dick & Carey Systems Model (High-Stakes / Technical / Clinical / Compliance)
* **Best For**: Safety-critical training, medical procedures, equipment operations, rigorous credentialing.
* **IDD Specialization**: Hierarchical task analysis decomposition, prerequisite entry behavior screening, parallel criterion-referenced test item mapping.

### 4. Cathy Moore Action Mapping (Performance-First Corporate Training)
* **Best For**: Sales enablement, customer support, leadership decision-making, performance gap closing.
* **IDD Specialization**: Anchored directly in a quantifiable business metric, focuses strictly on **observable actions** learners must do, centers on branching scenario practice, ruthlessly eliminates "nice-to-know" content dumps.

### 5. Backward Design / UbD (Academic, Higher Ed, Deep Conceptual Learning)
* **Best For**: University courses, K-12 curricula, professional certifications requiring deep conceptual transfer.
* **IDD Specialization**: Stage 1 Desired Results (Enduring Understandings & Essential Questions), Stage 2 Assessment Evidence (GRASPS authentic performance tasks), Stage 3 WHERETO learning plan.

### 6. 4C/ID Model (Complex Cognitive Skills & Technical Architecture)
* **Best For**: Software architects, emergency commanders, diagnostic clinicians, troubleshooting engineers.
* **IDD Specialization**: 4 distinct components: Whole Learning Tasks, Supportive Information (theory presented before practice), Procedural Information (just-in-time job aids during practice), Part-Task Practice.

## 3. How to Lead an IDD Stakeholder Review & Sign-Off

The primary purpose of an IDD is to **prevent scope creep and expensive rework** during the development phase.

### Best Practices for IDD Sign-Off:
1. **Never Show a 50-Page Document Without an Executive Summary**: Use Section 1 of the IDD to capture the business problem, target metric, and scope boundaries on 1 page.
2. **Highlight In-Scope vs. Out-of-Scope Explicitly**: Stakeholders often assume video shoots, mobile apps, or LMS translations are included unless explicitly marked Out-of-Scope.
3. **Lock the Learning Objectives**: Stakeholders must understand that changing learning objectives after IDD sign-off requires revising storyboards and test banks (Change Control trigger).
4. **Establish the Review Cadence**: Secure agreement on the 3-day turnaround rule for SME feedback to prevent project stalls.
